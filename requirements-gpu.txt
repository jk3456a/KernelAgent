# GPU-side Python layer for KernelAgent, installed into a venv with uv.
#
# Deliberately NOT baked into the Dockerfile. The image carries only what a venv
# physically cannot (CUDA toolchain, Nsight, rsync, the uv binary); everything
# here moves with a re-provision instead of a rebuild:
#
#     rsync requirements-gpu.txt <host>:kernelagent-requirements.txt
#     ssh <host> 'bash -s' < scripts/setup_remote_venv.sh
#
# Named requirements-gpu.txt, not requirements.txt, because this repo's own deps
# live in pyproject.toml and the control machine must stay torch-free -- a root
# requirements.txt invites exactly the wrong `pip install -r` on the laptop.

# --- Indexes: the ORDER is load-bearing -------------------------------------
# uv consults *additional* indexes (--extra-index-url) FIRST and treats the
# default index (--index-url) as the lowest-priority fallback. Combined with the
# default --index-strategy=first-index -- stop at the first index that has a
# package, and lock resolution to that index -- the channel listed as "extra" is
# the one that wins.
#
# So the arrangement below is deliberate, not backwards:
#
#   extra   = PyTorch's cu126 channel  -> consulted first, wins for torch/triton
#   default = the cluster PyPI mirror  -> fallback for anything cu126 lacks
#
# Writing it the other way round is the bug this file exists to prevent. With
# PyPI (or any mirror of it) as the *extra* index, torch==2.13.0 resolves to the
# CUDA 13 build -- nvidia-cublas 13.1.1.3, nvidia-cudnn-cu13, nvidia-nccl-cu13 --
# because first-index then locks resolution to PyPI. The version string is
# byte-identical either way, so nothing looks wrong until the host's CUDA 12
# driver refuses to load it at the first import.
#
# Measured, not assumed: a bogus *default* index alongside a real extra one
# installs fine and never contacts the default; a bogus *extra* index alongside
# a real default fails outright. tests/test_gpu_env_layers.py pins the ordering.
#
# The modern --index / --default-index spellings are rejected inside a
# requirements file ("Unexpected '-'"), so these stay on the legacy flags.

# The cluster-local PyPI mirror. Reachable from the GPU host, not from outside
# the cluster -- which is fine, this file is only ever read there. It is also
# the only index measured to serve its own *files*: pypi.org and
# download.pytorch.org answer, but the hosts their wheels actually live on
# (files.pythonhosted.org, download-r2.pytorch.org) are cut off by the cluster
# whitelist proxy.
--index-url https://pypi.hs1.paratera.com/root/pypi/+simple

# That mirror serves Traefik's default self-signed placeholder certificate
# (CN = TRAEFIK DEFAULT CERT), so no CA store can validate it. Declared once
# here in pip's spelling; setup_remote_venv.sh translates it to uv's
# --allow-insecure-host, which uv needs because it parses this flag and then
# ignores it.
--trusted-host pypi.hs1.paratera.com

# Wins for torch and triton per the ordering above, and it carries their nvidia-*
# dependencies too, so the CUDA 12 set stays internally consistent.
--extra-index-url https://download.pytorch.org/whl/cu126

# --- Pins -------------------------------------------------------------------
# cu126 rather than 13.x because a CUDA 12 driver cannot load a CUDA 13 runtime.
# sm_90 loses nothing by it: Hopper predates the 13.0 cutoff, which dropped only
# Maxwell / Pascal / Volta. Every cu12x wheel bundles its own CUDA runtime, so
# the host driver only has to clear the CUDA 12 family floor (525.60.13), not
# the exact minor -- which is why this runs fine on a 12.2 driver.
torch==2.13.0

# Not a downgrade. 3.7.1 is both the newest release and the one torch 2.13.0
# pins, so "latest Triton" and "the Triton torch was built against" agree here.
# Triton links no CUDA at all -- its wheel declares zero nvidia-*/cuda-* deps and
# vendors ptxas 12.8.93, itself a CUDA 12 build. (It ships a 13.1.80
# ptxas-blackwell as well, but upstream routes Hopper away from it deliberately.)
# CUDA minor-version compatibility covers the 12.8-vs-12.6 gap.
#
# Raising this alone will break torch.compile: inductor tracks a specific Triton
# API, so the pair moves together or not at all.
triton==3.7.1

numpy
