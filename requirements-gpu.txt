# GPU-side Python layer for KernelAgent, installed into a venv.
#
# Baked into the GPU Docker image: the Dockerfile creates /root/venv-ka with
# `python3 -m venv` and `pip install -r` this file. Index configuration lives
# in the Dockerfile, not here -- the build drives pip through the Tsinghua
# PyPI mirror, and torch resolves from that mirror rather than a cu126 channel.
#
# Named requirements-gpu.txt, not requirements.txt, because this repo's own deps
# live in pyproject.toml and the control machine must stay torch-free -- a root
# requirements.txt invites exactly the wrong `pip install -r` on the laptop.

# --- Pins -------------------------------------------------------------------
# Option A: no PyTorch cu126 channel directive. torch==2.13.0 resolves from the
# Tsinghua PyPI mirror, which serves the generic (CUDA 13 runtime) wheel. That
# is acceptable here because the base image (infra/nvidia-pytorch:latest)
# already ships a CUDA runtime matched to its torch, and the host driver is
# assumed to support it. If you ever need the CUDA 12 build instead, the
# rollback is to re-add the cu126 channel as pip's first-ranked index -- the
# ordering is load-bearing, see git history of this file.
torch==2.13.0

# Not a downgrade. 3.7.1 is both the newest release and the one torch 2.13.0
# pins, so "latest Triton" and "the Triton torch was built against" agree here.
#
# Raising this alone will break torch.compile: inductor tracks a specific Triton
# API, so the pair moves together or not at all.
triton==3.7.1

numpy
